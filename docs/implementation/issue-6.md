# Issue #6: 封签瓶与解锁阈值

任务：[完成封签瓶按累计收取数揭封](https://github.com/LeoYoungLH/Game_Color_Bottle/issues/6)。本票在现有同步会话结算中实现封签；不提前接入广告、撤回或存档。

## 行为

- 关卡为非空瓶配置正整数 `sealThreshold`。开局封签状态阻止其接水、倒水及被收集，公开快照仅保留容量、解锁阈值、状态，不显示颜色。实际收取数作为唯一进度，倒水步数和待收满瓶不计入。
- 每次收取后按瓶 ID 顺序检查解锁阈值，符合条件的瓶子只揭封一次，并在同一动作的后续扫描中参与收取。阈值保留在揭封后的公开瓶状态中，供后续撤回、存档实现参考；后续模块仍需保存完整真实层和显露信息。
- S08 的解锁阈值为 2，先收两只原有颜色瓶，再将蜜黄倒入已开放的封签瓶。S09 解锁阈值为 5，完成第 4 次收取仍锁，第 5 次真实收取使蜜黄满瓶揭封并在同一动作中收走。两关有固定手工解法，均无需广告帮助，也不依赖封签瓶提前参与来达到阈值。

## 验证

- 公开会话测试覆盖双向拒绝、选瓶拒绝、揭封前不泄漏颜色、2 次与 5 次阈值、4 次后倒满无匹配瓶仍不揭封、揭封事件只出现一次、同动作连锁及关卡回放。
- 浏览器实测 S08 的 0/2、1/2 与 2/2 揭封状态：瓶位不移动，揭封后蜜黄可见并可接水；S09 4/5 仍遮盖，第 5 次收取后封签满瓶一并收走并通关。手机尺寸检查 11 瓶保持 6+5、进度文字未横向溢出。
- 无异步倒水/收取动画，故 T16 中动画期间输入串行化不在此票声称验收；撤回与保存恢复的跨揭封回退由后续任务完成。

## 审查边界

规范轴发现旧稿术语不一致，现统一使用词表的“解锁阈值”。规格轴确认 T06 行为，但指出玩家快照无法重建尚未公开的真实层：这属于有意的隐藏信息边界，不是可信存档格式。当前公开状态足以观察封签的阈值、开闭和进度；未来撤回及存档任务必须另设受信任的完整状态保存/恢复入口，并验证跨揭封回退。这里不以玩家可见快照冒充该接口。
