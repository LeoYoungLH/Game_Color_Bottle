# Issue #3: 收集目标与下一关

任务：[补齐目标队列与下一关流程](https://github.com/LeoYoungLH/Game_Color_Bottle/issues/3)。基于 Issue #2 的网页验证版本，不将当前视觉样式当成最终定稿。

## 行为

- 三个当前收集槽按固定顺序取得目标；每次收取只消耗一个目标，若尚有库存则给原槽补位。
- 未匹配的单色满瓶在原位置等待；新目标出现后按瓶位与槽位顺序重新扫描，直到没有匹配。一次倒水返回全部收取事件。
- 下一待分配目标由共享队列预告，不指向特定槽。关卡库存与每种颜色的四单位收集需求相等；耗尽后槽位显示完成。
- 每次开局生成不同会话身份。胜利后只允许通过显式入口进入清单下一关；S05 显示本版完成。
- S04/S05 固定配置和手工回放各三步，两关均保留两个普通空瓶及两个仍锁定的广告空瓶。

## 验证

- 通过公开会话入口检查目标守恒、满瓶等待、同动作连锁、已收位置稳定、一次胜利与新局身份。
- 五个固定关卡的手工轨迹均回放至胜利，无需广告帮助。
- 实际浏览器点击 S04 三步通关后进入 S05，再点击三步至末关完成；验证预告、进度和末关无下一关按钮。
- `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run build` 为检查命令。
