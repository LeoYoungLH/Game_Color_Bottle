## What to build

玩家做好待收满瓶后，交付台能更新目标并连续收取；最终只结算一次，并能进入下一验证关。交付 S04–S05，补齐从开局到下一关的目标库存流程。

依据当前《拾色工坊 MVP》规格；通过游戏会话公开入口验证玩家可见行为，并补充本票所需的少量浏览器检查。规格验收引用：T04、T05、T16、T17、T18。这些编号是验收场景，不是 GitHub Issue 编号。

## Acceptance criteria

- [ ] 采用有限、确定的目标库存；三个槽先取得当前目标，收取后按稳定顺序从未分配目标补充，不复制需求。
- [ ] 没有匹配目标的满瓶留在原位；新目标匹配已满瓶时持续收取到链条稳定，同一瓶不被多个槽重复收走。
- [ ] 一条动作链的目标、收取数和瓶子移除作为完整结果提交；动画中重复输入不重复结算，保留已收走的位置。
- [ ] 预告明确标为下一待分配目标，不承诺共享目标必定属于某个特定槽。
- [ ] 本关必要收取完成后只触发一次胜利；空瓶和锁定广告位不阻塞；当前清单最后一关不跳到不存在的内容。
- [ ] 进入下一关建立新的对局代次，提供后续广告结果失效所需的公开身份边界。
- [ ] S04–S05 可演示满瓶等待和连续收取，游戏会话与关键浏览器流程覆盖链条及导航。
