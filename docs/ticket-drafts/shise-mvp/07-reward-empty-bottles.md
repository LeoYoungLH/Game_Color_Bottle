## What to build

玩家在缺少接水空间时选择一个广告空瓶，获得成功结果后原地开放，取消或失败则返回原局面。用这条流程建立其他奖励复用的请求身份与结果处理边界。

依据当前《拾色工坊 MVP》规格；通过游戏会话公开入口验证玩家可见行为，并补充本票所需的少量浏览器检查。规格验收引用：T08、T09、T10。这些编号是验收场景，不是 GitHub Issue 编号。

## Acceptance criteria

- [ ] 每关恰好两个空的锁定位，计入总瓶位但不取代免费空瓶；未解锁不能接水或倒水。
- [ ] 明确标注模拟广告，提供成功、提前关闭、失败和无可用广告结果；一次成功只解锁所选瓶，另一个保持状态。
- [ ] 解锁后可正常接水、倒水、装满及被收取；收走后不无限补空瓶。
- [ ] 请求绑定奖励目标、关卡、对局代次和唯一请求标识；重复、延迟、旧关或旧代次结果不重复发奖。
- [ ] 等待结果时阻止背景对局动作；非成功结果不消耗瓶位或改变棋盘；进入新关重新生成两个锁定位。
- [ ] 从界面发起模拟请求，再通过会话观察结果并完成倒水；不接真实 SDK，不读取登录或广告凭据。
