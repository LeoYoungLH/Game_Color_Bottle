## What to build

玩家看到封签门槛，完成指定数量的实际收取后揭封并继续通关。交付 S08–S09，以不同阈值验证计数与开放条件。

依据当前《拾色工坊 MVP》规格；通过游戏会话公开入口验证玩家可见行为，并补充本票所需的少量浏览器检查。规格验收引用：T06、T16。这些编号是验收场景，不是 GitHub Issue 编号。

## Acceptance criteria

- [ ] 封签瓶开放前不能接水或倒水，显示门槛与当前收取进度；阈值来自关卡定义，不写死为 5。
- [ ] 只有实际收走满瓶才增加进度；以门槛 5 验证收取 4 瓶仍锁定，仅倒满不解锁，第 5 次实际收取才开放。
- [ ] 一次连续收取跨过门槛时只揭封一次；揭封后的瓶子正确参与同一次后续结算。
- [ ] S08–S09 使用至少两种阈值，提供在未使用封签瓶之前就能达到门槛的无广告路径，避免解锁循环依赖。
- [ ] 通过会话公开行为和局内封签表现完成验收；提供后续撤回与保存恢复可观察的完整状态。
