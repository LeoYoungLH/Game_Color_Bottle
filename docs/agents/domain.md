# Domain docs

## 布局

本仓库采用单一领域布局：根目录 `CONTEXT.md` 保存词表，`docs/adr/` 保存架构决策记录。

## 阅读时机

探索代码或讨论领域设计前，先读 `CONTEXT.md`，再读 `docs/adr/` 中与当前工作相关的记录。

若文档或目录不存在，继续工作，不把缺失当作错误，不预先创建空文件。`domain-modeling` 在术语明确或决策达成时按需创建文档。

## 使用规则

- 在需求、代码、测试和设计讨论中使用词表定义的领域名称。
- `CONTEXT.md` 仅保存领域词汇，不放实现方案、进度或需求清单。
- 如需新概念，先核对是否已有对应术语；未明确的词义在讨论中澄清，再更新词表。
- ADR 只记录已经达成、具有真实取舍且改变成本较高的决策。
- 若建议与已有 ADR 冲突，明确指出记录编号与需要重新评估的原因。

若项目后续出现多个独立领域，重新评估布局，再引入 `CONTEXT-MAP.md`；当前不创建多领域结构。
